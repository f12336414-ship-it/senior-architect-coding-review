# v0.4.0 — 先复用、按需分层与实际行为验证

## 核心变化

- 保留需求澄清、独立反方审查、证据裁决及高风险批准门禁。
- 不默认生成 Work/Domain 或 Controller/Service/Repository；根据共同变化、规则所有权和真实隔离需求选择结构。
- 编码前核对项目、框架、标准库和官方 SDK 能力；只为已证实的缺口自研。
- 新增抽象删除测试和双向反证，既检查透传层，也防止简化时丢失事务、安全或共享规则。
- 增加四个独立上下文 Agent 场景、可重放代码和验证记录；明确区分关键词 smoke 与代码行为验证。

## 验证与限制

- 29 项仓库单元测试通过，其中包括 3 项保存产物重放。
- 三个实际代码任务共 26 项行为测试通过；支付需求未知场景保持 discovery / G1 NOT_READY，未直接添加重试。
- 三项实现经过独立上下文反方复核，未发现可复现缺陷。
- 仓库结构、Skill 包及差异空白检查通过。

测试是人工构造的小型 Python 场景，不是生产 PR；没有多模型统计、C#/.NET 等框架实跑或人类专业评审。重放保存产物不代表未来 Agent 生成必然正确。

完整证据：[实测记录](https://github.com/f12336414-ship-it/senior-architect-coding-review/blob/v0.4.0/evals/results/2026-11-09/README.md)。

## 升级注意

这是 0.x 阶段的工作流调整：普通局部写入仅在既有所有者、schema、事务语义、可验证失败恢复且不触及高风险边界时进入 medium-local。升级受控项目时审查 [fast-path](https://github.com/f12336414-ship-it/senior-architect-coding-review/blob/v0.4.0/skill/senior-architect-coding-review/references/fast-path.md) 差异。

Skill 名称、安装路径、现有 Schema 和高风险批准要求不变。回答契约评测 JSON 新增 `evaluation_scope` 和 `semantic_correctness_verified` 字段。
