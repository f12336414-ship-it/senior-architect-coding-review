# 真实执行型场景

这些是小型、人工构造的代码任务，不是生产 PR，也不是关键词评分输入。
每次把单个场景复制到独立临时目录，将 `request.md`、源码、测试和待测 Skill 路径交给未看到评分标准的 Agent。
不要让 Agent 读取其他场景、此说明中的判分标准或之前的结论。

| 场景 | 可执行验收 | 独立审查重点 |
| --- | --- | --- |
| local-write | 6 个测试：更新、无效输入、缺失、引号、调用方回滚、失败不回滚调用方工作 | 沿既有 SQLite 操作，无无意义分层；保留事务所有权 |
| csv-export | 5 个测试：空、普通、转义往返、单次迭代、既有导出 | 复用已有 `_csv_text` 和标准库，不复制转义器或增加等价包装 |
| shared-rules | 3 个测试，含两个入口的状态转换矩阵 | 保留共享规则所有者，不能为减少层次而把规则复制到入口 |
| payment-unknown | 保留文件哈希，检查实际响应和文件差异 | 识别未知支付结果和幂等语义，澄清决策性问题，不默认实施重试 |

前三个场景的初始实现有 `NotImplementedError`，验收测试应先失败。这是有意的任务输入，不应纳入普通仓库单元测试发现路径。Agent 完成后运行原始测试，保留 diff、响应、命令/退出码、Skill 文件哈希、权限和运行次数。

评价分开记录：代码行为是否通过、结构/复用选择是否有证据、需求与反方审查是否保留。不要用目录名或“提到了复用”判分；额外类型有真实隔离价值时可以合理存在。

单次小样本通过不能推出所有模型、语言、生产系统都有效。关键词 smoke fixture 仍仅用于检查旧评测器本身。
